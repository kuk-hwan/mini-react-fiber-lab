            01 / INPUT

              업데이트 큐에 변경을 넣습니다. 같은 작업 안의 여러 변경은 한 렌더링으로 처리합니다.
            
    
          
    
          
    
            02 / RENDER · YIELD
            
    Fiber 작업 트리
    
            
    
              child → sibling → return으로 이동합니다. 시간 예산을 넘으면 다음 작업으로 양보합니다.
            
    
          
    
          
    
            03 / COMMIT
            
    Diff → Patch
    
            
    공유 Diff 모듈로 계획을 만든 뒤 DOM을 동기적으로 변경하고 effect를 실행합니다.

    1. CREATE 새 노드를 생성하고 삽입
      2. 
              
    2. REMOVE 사라진 노드를 삭제

      4.

      5.

              편집 횟수를 보장하지는 않습니다.
            
    
          
    
          
    
            HOOKS & MEMORY
            
    함수가 다시 실행되어도
    
            
    
              FunctionComponent.hooks 배열은 인스턴스에 남아 있습니다. 매 렌더링에서
              호출 순서로 같은 슬롯을 찾아 상태를 이어갑니다.
            
    
            
    
              [0] state[1] state[2] memo[3] effect
            
    
            
    
              useMemo는 의존성을 Object.is로 비교합니다. useEffect는 commit 뒤 실행되며, 의존성이
              바뀌거나 unmount될 때 cleanup을 호출합니다.
            
    
          
    
          
    
            BROWSER COST
            
    DOM이 항상 느린 건 아닙니다
    
            
    
              크기·위치 변화는 layout(reflow), 색상 변화는 paint를 유발할 수 있습니다. 특히 DOM
              쓰기와 레이아웃 읽기를 번갈아 하면 강제 동기 레이아웃 비용이 커질 수 있습니다.
            
    
            
    
              Virtual DOM도 비교 비용이 있습니다. 이 구현은 변경 범위를 줄이고 commit에서 쓰기를
              모으는 방법을 보여줍니다. 더 빠르다는 일반적인 보장은 하지 않습니다.
            
    
          
    
          
    
            HONEST BOUNDARIES
            
    실제 React와 다른 점
    
            
    
              교육용 Fiber 구조입니다. lanes·우선순위·Suspense·SSR·Hydration·Error Boundary는
              구현하지 않았습니다. Hook은 루트만 사용하며 컴포넌트는 단일 VNode 또는 null을
              반환합니다.
            
    
            
    
              작업 단위 사이에 양보하지만 단일 컴포넌트 함수 실행과 commit은 중단하지 않습니다.
              effect는 commit 후 동기 실행하므로 paint 이후 실행을 보장하지 않습니다.
